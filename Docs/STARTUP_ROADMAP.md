# Krepton Analytics — Roadmap: Diploma → Soft Startup

> Цель: довести POC до уровня, где его можно защитить как диплом **и** спокойно показать первым реальным пользователям как зародыш продукта.  
> Принцип: сначала ценность и доверие, потом платный Azure и монетизация.

---

## Что думаю о твоём плане

В целом **да, последовательность правильная**. Три маленькие поправки:

1. **GDPR-минимум не откладывать «на потом после всех фич».** Для диплома он обязателен, для стартапа — блокер доверия. Делаем *параллельно* с фичами лёгкий legal-скелет (Privacy / Terms / delete account / disclaimers), а полный EU-review — отдельной фазой.
2. **Юнит-тесты начинать уже в фазе фич**, а не ждать «фазы тестирования». Иначе к концу накопится долг. Фаза 3 = углубление (e2e, security, regression).
3. **Знакомых можно звать раньше полного Azure.** Локально / временный free-tier / туннель — уже дают фидбек по UX и импорту. Платный Azure (~€10/мес) — ближе к soft launch, как ты и планируешь.

### 1.2.1 Import statement corpus (обязательная проверка)

Универсальный импорт нельзя считать «готовым» на одном Revolut-файле. Нужен **корпус реальных/анонимизированных выгрузок** и прогон каждого через preview.

- [ ] Собрать как можно больше вариантов `.xlsx` / `.csv` (PDF не поддерживаем):
  - Revolut (account statement) — уже есть baseline
  - Trading 212 (history export)
  - Interactive Brokers (Activity / Trade Confirm Flex CSV или Excel)
  - Charles Schwab / Fidelity (если удастся найти публичные/свои выгрузки)
  - eToro / другие EU-брокеры по возможности
  - «ломаные» варианты: лишние колонки, currency в price (`USD 340.61`), нет отдельной Currency, переименованные headers, дивиденды/cash rows
- [ ] Хранить только **анонимизированные** копии (убрать account id / имя / IBAN); не коммитить PII. Идеально — `Docs/statements/` + gitignore на сырые файлы, в репо — маленькие synthetic fixtures для CI
- [ ] На каждый файл зафиксировать результат в таблице (можно в issue / Notion / этот же раздел):

  | Файл / брокер | Формат   | Mode (heuristic / ai_schema) | Trades ok? | Проблемы | Нужен фикс? |
  | ------------- | -------- | ---------------------------- | ---------- | -------- | ----------- |
  | …             | xlsx/csv | …                            | ✅/❌        | …        | …           |


- [ ] Критерии приёмки файла: BUY/SELL распознаны; дивиденды/cash skipped; currency корректна (колонка **или** embedded в price); preview без 5xx; пользователь может confirm
- [ ] Повторять прогон после каждого изменения heuristic / AI schema / value parsers
- [ ] В CI оставить synthetic fixtures; полные реальные statements — ручной / локальный regression checklist перед friend beta

Связь с GDPR: в AI уходит только truncated sample; полные statements в логи/Gemini не отправлять.

## Phase 4 — Deploy (готово) + friend beta

### 4.1 Когда деплоили

**Сделано 2026-09-02.** Домен `kreptonanalytics.com` куплен, деплой поднят руками через Azure Portal (осознанно, не CLI/IaC — для практики). Автодеплой на push в `main` настроен.

- [x] Домен куплен и настроен через Cloudflare DNS
- [x] Azure resource group + Postgres Flexible Server + Container Apps + Static Web Apps
- [x] Кастомные домены + SSL: `www.kreptonanalytics.com`, `api.kreptonanalytics.com`
- [x] SMTP (Resend) — verification email доставляется
- [x] Google OAuth настроен на прод-домене
- [x] CD: GitHub Actions автодеплой на push в `main` (build → GHCR → Container Apps + Static Web Apps)
- [x] Rate limiting (defense-in-depth) на все `GET /portfolio/*` — 120 req/min на пользователя

### 4.2 Cost-aware Azure — что взяли фактически

Цель была **~€10/мес или меньше**; итоговый выбор:

| Компонент     | Что взяли                                                                             |
| ------------- | -------------------------------------------------------------------------------------- |
| App (API)     | Azure Container Apps, scale-to-zero (North Europe) — не платим, когда никто не заходит |
| DB            | Azure Database for PostgreSQL Flexible Server, smallest Burstable SKU (North Europe)   |
| Static FE     | Azure Static Web Apps, free tier (East US 2 — единственный вариант free-плана)         |
| SMTP          | Resend free tier + свой домен                                                          |
| Observability | Azure Log stream (pino JSON stdout) + Container Apps Portal metrics                    |

Пауза/экономия: см. [Cost & Idle Runbook в deployment.md](diploma/thesis/docs/02-technical/deployment.md#cost--idle-runbook) — останавливать нужно только Postgres Flexible Server, Container Apps и Static Web Apps уже ничего не стоят в простое.

### 4.3 Что нашли на живом стенде (не видно было на localhost)

Прямая польза от раннего деплоя — реальные баги, а не только рубрика:

- GHCR требует lowercase repo name; health probes указывали на порт 80 вместо 3001; SWA без `staticwebapp.config.json` 404-ит на прямых ссылках; Google OAuth `origin_mismatch` без прод-домена в Authorized origins.
- **Критичный:** бесконечный polling-луп на Screener и Backtesting для новых аккаунтов с пустым watchlist/портфелем (135 req/sec) — нашли только на реальном новом аккаунте в проде. Пофикшено + добавлен rate limiter как защита на будущее.

## Definition of Done по горизонтам

### Diploma-ready

- Сильное демо end-to-end  
- GDPR-минимум + дисклеймеры  
- Тесты на критичную логику + security notes в Docs  
- Честные цифры (без mock equity на пустом аккаунте)

### Soft-startup-ready (друзья)

- Всё из diploma-ready  
- Privacy/Terms доступны в UI  
- Delete account работает  
- Импорт: ≥3 разных брокера/формата из корпуса §1.2.1 проходят preview→confirm «с первого раза»  
- Список багов от 3+ внешних юзеров и приоритеты

### Real launch-ready (позже)

- Платежи, EU hosting в Privacy = факт, SMTP/домен, monitoring, retention-фича
