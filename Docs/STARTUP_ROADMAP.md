# Krepton Analytics — Roadmap: Diploma → Soft Startup

> Цель: довести POC до уровня, где его можно защитить как диплом **и** спокойно показать первым реальным пользователям как зародыш продукта.  
> Принцип: сначала ценность и доверие, потом платный Azure и монетизация.

---

## Что думаю о твоём плане

В целом **да, последовательность правильная**. Три маленькие поправки:

1. **GDPR-минимум не откладывать «на потом после всех фич».** Для диплома он обязателен, для стартапа — блокер доверия. Делаем *параллельно* с фичами лёгкий legal-скелет (Privacy / Terms / delete account / disclaimers), а полный EU-review — отдельной фазой.
2. **Юнит-тесты начинать уже в фазе фич**, а не ждать «фазы тестирования». Иначе к концу накопится долг. Фаза 3 = углубление (e2e, security, regression).
3. **Знакомых можно звать раньше полного Azure.** Локально / временный free-tier / туннель — уже дают фидбек по UX и импорту. Платный Azure (~€10/мес) — ближе к soft launch, как ты и планируешь.

## **Phase 0 — Legal skeleton (минимум GDPR / MiFID-safe)**

**Делать коротко, не ждать конца разработки.**

- [ ] **Footer / Profile: ссылки на Privacy Policy и Terms of Service**
- [ ] Дисклеймер: *analytical tool, not investment advice* (регистрация, rebalancing, AI-блоки)
- [ ] **Delete account** (не только wipe portfolio) — hard delete user + related data
- [ ] Пометка AI-контента («Generated by AI» + hallucination caveat)
- [ ] Cookie / session note: JWT в HttpOnly cookies уже ок; кратко описать в Privacy

Связанный док: `Docs/MAYBE-STARTAP.md`

## Phase 1 — Features (диплом + будущий продукт)

Продолжаем фичи, которые **и на защите звучат сильно, и потом остаются в продукте**.

### 1.1 Product / UX

- [x] Смена темы — Stage 1: design tokens + App Shell (header/sidebar) under WCAG 2.1 AA
- [x] Смена темы — Stage 2: Dashboard contrast (switcher, health amber, dividers/grid)
- [x] Смена темы — Stage 3: remaining authenticated pages
- [ ] Смена темы — Stage 4: Auth
- [ ] Смена темы — Stage 5: Welcome / Landing
- [ ] Onboarding empty-states → путь «Add position / Import report» (уже начато)
- [ ] Спокойный UX: меньше «казино», больше monthly check (allocation, drift, equity)



### 1.2 AI (только честные use-cases)

Приоритет — то, что уже в духе продукта (факты / объяснения / парсинг), **не** «купи/продай».


| Idea                                   | Зачем                             | Риск                               |
| -------------------------------------- | --------------------------------- | ---------------------------------- |
| News summary по тикерам портфеля       | Anti-noise, сильное демо          | Низкий (факты + disclaimer)        |
| Explain alignment (уже есть база)      | Понятность rebalancing            | Низкий                             |
| AI-парсер брокерских отчётов           | Масштаб импорта без 100 парсеров  | Средний (качество JSON, валидация) |
| Sentiment 🟢/🟡/🔴 у тикеров в summary | Дешёвое расширение того же prompt | Средний (не превращать в advice)   |


Отложить / не в Phase 1: price prediction, «что купить», торговые сигналы.

### 1.3 Product ideas (после / рядом, если хватает времени)

Из `Docs/ВозможныеФичи.md` — лучшие для стартапа после дипломного ядра:

1. **Deposit-based rebalancing** («куда положить $1000 без продаж») — главный retention-кандидат
2. **ETF overlap / false diversification**
3. Dividend calendar (если нужно ещё «мясо» на защиту)



### 1.4 Engineering hygiene (внутри фазы фич)

- [ ] Юнит-тесты на новую логику сразу (auth, rebalancing math, money display, parsers)
- [ ] Не копить magic / мёртвые mock-данные на дашборде
- [ ] Проверка: баланс / equity / P&L согласованы (см. заметку в ВозможныеФичи)

## Phase 2 — Full app review под законы Европы

Отдельный проход «как аудитор», не как фича-спринты.

### 2.1 GDPR checklist

- [ ] Privacy Policy: что храним (email, hash, сделки, IP/logs), где (желательно EU region), зачем
- [ ] Право на доступ / экспорт данных (у вас export уже есть — оформить как GDPR data export)
- [ ] Право на забвение: delete account + подтверждение
- [ ] Передача в США (Gemini): EU–US DPF / оговорка в Privacy
- [ ] Минимизация логов (не логировать PII / verification links / токены)



### 2.2 MiFID II / «не советник»

- [ ] Rebalancing UI = калькулятор отклонений, без императива «купи N акций X»
- [ ] AI copy review: убрать любые buy/sell формулировки
- [ ] Дисклеймеры на всех чувствительных экранах



### 2.3 EU AI Act (limited risk)

- [ ] Прозрачность: пользователь видит, что текст от ИИ
- [ ] Ошибка/галлюцинация disclaimer под AI-блоками
- [ ] Quota / cache (уже есть задел) — держать предсказуемые лимиты



### 2.4 Hosting note (для текста диплома / Privacy)

Пока локально — ок. В Privacy заранее заложить целевой EU region (Azure West Europe / Sweden Central / Hetzner EU и т.д.).

## Phase 3 — Testing & security



### 3.1 Unit → integration

- [ ] Backend: auth, portfolio math, rebalancing, import parsers, FX conversion
- [ ] Frontend: selectors, money display, critical reducers
- [ ] API integration smoke (Jest / supertest там, где уже принято в репо)



### 3.2 Security pass (диплом + стартап)

- [ ] Auth: HttpOnly JWT only, bcrypt, step-up на export / password change (уже есть)
- [ ] CSRF / CORS / rate limits review
- [ ] Upload: memory-only, size/type limits, no path traversal
- [ ] Dependency audit (`npm audit` + ручной взгляд на критичное)
- [ ] Secrets: `.env` не в git, пример в `.env.example`
- [ ] Threat model light: session fixation, IDOR по portfolio owner token, mass assignment



### 3.3 Manual / diploma demo script

- [ ] Сценарий защиты: register → verify → import/add → dashboard → rebalancing → AI explain → export → delete
- [ ] Сценарий «новый пустой аккаунт» без фейковых цифр

## Phase 4 — Deploy (поздно и дёшево) + friend beta



### 4.1 Когда деплоить

Согласен с тобой: **не жечь €10/мес сейчас**. Деплой ближе к концу / soft launch.

До Azure можно:

- локальные демо знакомым
- при необходимости — временный free sandbox (с пониманием лимитов)



### 4.2 Cost-aware Azure target (черновик)

Цель: **~€10/мес или меньше** на старте.


| Компонент     | Идея экономии                                                                        |
| ------------- | ------------------------------------------------------------------------------------ |
| App           | один маленький App Service / Container Apps / дешёвый VM                             |
| DB            | Azure PostgreSQL flexible smallest / или managed EU Postgres вне Azure, если дешевле |
| Static FE     | Static Web Apps / CDN                                                                |
| SMTP          | Brevo/Resend free tier + свой домен (не Gmail)                                       |
| Observability | минимум: logs + uptime ping                                                          |




### 4.3 Friend beta (параллельно с деплоем)

- [ ] 3–10 знакомых инвесторов / «почти инвесторов»
- [ ] Короткий бриф: что продукт **не** брокер и **не** советник
- [ ] Собрать: импорт (какой брокер?), понятность Health/Rebalancing, доверие к цифрам, «зачем вернуться через месяц»
- [ ] Завести простой feedback log (Notion / issue labels: `ux`, `bug`, `data`, `import`)

## Phase 5 — После защиты (настоящий soft startup)

Не смешивать с дипломным дедлайном, но держать в голове:

1. Stripe + реальная `/subscription` (SCA, 14-day withdrawal checkbox для EU)
2. Домен + нормальная почта (меньше spam)
3. Killer loop: **deposit-based rebalancing** (+ optionally ETF overlap)
4. Надёжность котировок (кэш, fallback provider, честные empty states)
5. Юрлицо / invoicing — когда появятся первые платящие

## Definition of Done по горизонтам



### Diploma-ready

- Сильное демо end-to-end  
- GDPR-минимум + дисклеймеры  
- Тесты на критичную логику + security notes в Docs  
- Честные цифры (без mock equity на пустом аккаунте)



### Soft-startup-ready (друзья)

- Всё из diploma-ready  
- Privacy/Terms доступны в UI  
- Delete account работает  
- Импорт хотя бы одного реального сценария «с первого раза»  
- Список багов от 3+ внешних юзеров и приоритеты



### Real launch-ready (позже)

- Платежи, EU hosting в Privacy = факт, SMTP/домен, monitoring, retention-фича
